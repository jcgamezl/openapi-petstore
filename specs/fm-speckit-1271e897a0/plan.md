### 2.2 Layer Dependency Rules (Constitution Principle 2)

The three-layer architecture enforces a **strict top-down dependency flow**:

```
configuration  →  api  →  repository
      ↓             ↓           ↓
  Spring wiring  Delegates   HashMap CRUD
  OAuth2 setup   Exception   (in-memory only)
  Swagger UI     handling
```

- `configuration` wires Spring beans and OAuth2; it may reference both `api` and `repository` types.
- `api` delegates implement generated interfaces and call into `repository` only.
- `repository` has **no upward imports** — it is a leaf layer.
- Cross-cutting utilities (`RFC3339DateFormat.java`, `ApiUtil.java`) are referenced by `api` and `OpenAPI2SpringBoot.java`; they must not import from `configuration`.

*Source: `score_modernization` (score: 48/100, confidence: high), coupling hotspot report, and file-scope dependency graph.*

### 4.1 Current Architecture

| Attribute | Value |
|---|---|
| **Pattern** | Layered (API → Delegate → Repository) |
| **Entry Point** | `OpenAPI2SpringBoot.java` — `@SpringBootApplication` bootstrap |
| **Inbound Interface** | Generated delegate interfaces (Spring MVC, via OpenAPI Generator scaffold) |
| **Business Logic** | Distributed across three delegate implementations (`PetApiDelegateImpl`, `StoreApiDelegateImpl`, `UserApiDelegateImpl`) |
| **Data Access** | Generic `HashMapRepository<T>` base class; three domain-specific extensions |
| **Cross-Cutting Concerns** | `ExceptionTranslator.java` (errors), `RFC3339DateFormat.java` (dates), `ApiUtil.java` (file uploads) |
| **External Services** | None (confirmed: `service_edges = []`) |
| **Storage** | Pure in-memory; no persistence (confirmed: `databases = []`) |

### 4.2 Coupling Hotspots (from `score_modernization`)

Two coupling hotspots were identified. Both are **dependency-driven** (library version coupling), not complexity-driven:

**Hotspot 1 — OAuth2 Security Triad:**
`ResourceServerConfiguration.java` ↔ `SecurityConfiguration.java` ↔ `PetApiDelegateImpl.java`

All three files are coupled through `spring-security-oauth2-autoconfigure:2.0.1.RELEASE`. When this library is replaced (required for Spring Boot 3.x), all three files must be refactored as a unit. Neither can be changed independently without risking a broken security configuration.

**Hotspot 2 — Pet Layer:**
`PetApiDelegateImpl.java` ↔ `PetRepository.java`

The most feature-rich domain pair. `PetApiDelegateImpl.java` (158 lines, CC rank #2) calls into `PetRepository.java` (48 lines, CC rank #4) for filtering operations. The modernization report flags an absence of an explicit interface abstraction layer — if a persistent data store is introduced later, this coupling will require careful management to avoid cascading changes.

## 8. Constraints & Non-Negotiable Rules

The following rules are derived directly from the Constitution's detected principles and must be observed throughout all implementation phases:

| Rule | Source | Constraint |
|---|---|---|
| **C1** | Constitution Principle 1 | `openapi.yaml` is the single source of truth. No request/response shape change may be coded before being reflected in `openapi.yaml` first. |
| **C2** | Constitution Principle 2 | Layer dependency direction is immutable: `configuration` → `api` → `repository`. No upward imports. |
| **C3** | Constitution Principle 3 | OAuth2 security MUST NOT be removed during Phase 3. The migration target is `spring-boot-starter-oauth2-resource-server`, not removal. |
| **C4** | Constitution Principle 4 | `Dockerfile` must be updated in every phase that changes Java version, Spring Boot version, or Maven packaging. |
| **C5** | Constitution Principle 5 | All new exception-to-HTTP mappings go into `ExceptionTranslator.java`. Delegates must not contain raw `try/catch` producing HTTP responses. |
| **C6** | Constitution Principle 6 | `RFC3339DateFormat.java` remains the canonical date formatter. No `SimpleDateFormat` or inline formatter may be introduced elsewhere. |
| **C7** | Constitution Principle 7 | `HashMapRepository.java` MUST NOT be modified to add persistence. Persistent storage = new implementation class behind the existing interface. |
| **C8** | Constitution C-3 | All dependency versions must be explicit strings (no Maven property placeholder ambiguity) by end of Phase 0 (T0-11). |
